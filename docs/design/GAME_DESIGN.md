# 카드 수집형 방치 RPG — 상세 기획서

## 0. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 장르 | 카드 수집형 방치(Idle) RPG |
| 클라이언트 | 최소 UI (전투 애니메이션 없이 결과 텍스트/숫자 중심) |
| 서버 검증 원칙 | 클라이언트 결과값을 신뢰하지 않고, 서버가 보유한 카드 스탯으로 전투/보상을 직접 재계산 |

### 바운디드 컨텍스트 (7개)

1. **Inventory** — 카드 보유 현황
2. **Enhancement** — 강화
3. **Synthesis** — 합성
4. **Progression** — 레벨업 (카드 인스턴스 성장)
5. **Economy** — 재화
6. **Mailbox** — 우편
7. **Battle/Stage** — 전투 판정 및 스테이지 진행

각 컨텍스트는 자신의 책임만 가지며, 여러 컨텍스트에 걸친 상태 변경(강화, 합성,
우편 수령, 전투 보상 지급)은 Application 레이어의 Use-case가 오케스트레이션하고,
실제 원자성은 트랜잭션으로 보장한다.

## 1. 카드 등급 체계

| 등급 | 기본 공격력 범위 | 가챠 획득 확률 |
|---|---|---|
| N (Normal) | 10 ~ 20 | 60% |
| R (Rare) | 25 ~ 40 | 30% |
| SR (Super Rare) | 50 ~ 80 | 8% |
| SSR (Special Super Rare) | 100 ~ 150 | 2% |

- 카드 원형 데이터(등급, 기본 스탯)는 `CardTemplate`(VO)로 정의.
- 실제 유저가 보유하는 카드는 `Card`(Entity) — 고유 ID, 원형 참조, 현재 레벨,
  현재 강화 단계를 가짐.

## 1-1. 인벤토리 슬롯 정책

- 인벤토리에 슬롯 상한이 존재한다 (구체적 수치는 **TBD** — 추후 밸런스 결정 필요)
- 유저 액션 시 상한 근접/도달 여부를 UI로 지속 경고
- 상한 초과가 예상되는 유저 자발적 액션(스테이지 진입, 강화 시도 등)은 사전에 차단한다
- **핵심 원칙**: 유저가 이미 액션을 시작한 시점(스테이지 진입 승인, 강화 시도 승인)
  이후에 발생하는 결과(스테이지 클리어 보상, 강화 파괴 환급 등)는 슬롯 상한과
  무관하게 무조건 지급한다. 유저의 노력 또는 확률적 결과로 발생한 보상은 어떤
  경우에도 유실되거나 롤백되지 않는다.

## 2. 강화 시스템

강화는 카드 **인스턴스** 단위로 적용되며, 등급과 무관하게 공통 강화 단계(+0 ~ +15)를 가진다.

| 강화 단계 구간 | 성공 확률 | 실패 시 처리 | 필요 골드 (단계당) | 필요 강화석 |
|---|---|---|---|---|
| +0 → +5 | 100% | — | 100 × 목표단계 | 1 |
| +6 → +10 | 70% | 실패해도 단계 유지 | 300 × 목표단계 | 2 |
| +11 → +15 | 40% | 실패 시 10% 확률로 카드 파괴 | 800 × 목표단계 | 3 |

- 강화 1단계당 카드 공격력 **+5%**
- 강화 파괴 시 보상으로 소모한 강화석의 50%를 우편으로 환급 (선택적 정책)

**동시성 이슈**: 동일 카드에 대한 동시 강화 요청 시 이중 처리 방지 필요.
재화 차감 + 카드 상태 변경(단계 증가 or 파괴)은 하나의 트랜잭션으로 처리.

## 3. 합성 시스템

| 레시피 | 소재 | 결과 |
|---|---|---|
| 등급 승급 합성 | 동일 등급 카드 3장 | 상위 등급 카드 1장 (확률표 적용) |
| 강화 재료 합성 | 동일 원형 카드 2장 + 골드 | 대상 카드 강화 단계 +1 (파괴 없음) |

### 등급 승급 확률표 (N×3 소모 예시)

| 결과 | 확률 |
|---|---|
| R 카드 획득 | 80% |
| 실패 (소재 중 1장만 소모, 나머지 환급) | 20% |

**동시성 이슈**: 소재로 지정된 카드들이 다른 요청(강화 등)에서 동시에 사용되지
않도록 소재 카드 검증 → 삭제 → 결과물 생성을 원자적으로 처리.

---

## 4. 레벨업 (Progression)

- 카드 인스턴스는 최대 레벨 **60**까지 성장
- EXP 곡선: `필요 EXP = 50 × level^1.5`
- 레벨 1당 공격력 **+2%**
- EXP 획득처: 스테이지 클리어 보상

---

## 5. 재화 체계 (Economy)

| 재화 | 용도 | 주요 획득처 |
|---|---|---|
| 골드 | 강화/합성 기본 소모 재화 | 스테이지 클리어 |
| 강화석 | 강화 전용 소모 재화 | 스테이지 보상, 우편 |
| 다이아 | 가챠 뽑기 재화 | 일일 출석, 이벤트 우편 |

- `Wallet`(Aggregate Root) — 유저별 재화 잔액 관리, 차감/지급 시 잔액 부족 검증.

---

## 6. 스테이지 / 전투

- 총 **100 스테이지**, 10 스테이지 단위로 챕터 구분
- 필요 전투력: `기본값 × 1.15^스테이지번호` (지수 증가)
- 유저 전투력 계산:
  `전투력 = Σ(카드 기본공격력 × (1 + 레벨보너스) × (1 + 강화보너스))`
- 클리어 조건: 유저 전투력 ≥ 스테이지 필요 전투력
- 클리어 보상: 골드 + EXP + 확률적 강화석/카드 드랍 → **우편함으로 지급**

**검증 원칙**: 클라이언트는 "스테이지 N 도전" 요청만 보내고, 서버가 유저의
현재 보유 카드 스탯을 직접 조회해 전투력을 재계산 후 클리어 여부를 판정한다.
클라이언트가 보낸 결과값(승패, 데미지 등)은 신뢰하지 않는다.

---

## 7. 우편 시스템 (Mailbox)

### 발송 트리거

- 스테이지 클리어 보상
- 일일 출석 보상
- 강화 파괴 시 환급 보상 (선택 정책)
- 이벤트/공지 보상 (대량 발송)

### 정책

- 만료 기한: 발송 후 **7일**, 만료된 우편은 배치 잡으로 정리
- 수령 시 중복 처리 방지: 조건부 갱신 또는 락으로 이중 지급 차단
- 대량 발송(전체 유저 대상 이벤트 보상)은 배치 처리로 분리 설계

## 8. 컨텍스트 간 트랜잭션 요약

| Use-case | 관련 컨텍스트 | 원자성이 필요한 이유 |
|---|---|---|
| EnhanceCard | Inventory, Economy | 재화 차감 + 카드 상태 변경(강화/파괴) |
| SynthesizeCard | Inventory, Economy | 소재 카드 소모 + 결과 카드 생성 |
| ClaimMail | Mailbox, Inventory, Economy | 우편 상태 변경 + 첨부물 지급 |
| ClearStage | Battle, Progression, Economy, Mailbox | 전투 판정 + EXP 지급 + 보상 우편 발송 |

모든 Use-case는 관련 트랜잭션을 통해 원자성을 보장하며,
도메인 레이어는 저장소 구현을 알지 못하고 Repository 인터페이스에만 의존한다.

## 9. 추후 조정 여지 (오픈 이슈)

- 강화 확률표는 초기 표준값으로, 실측 후 밸런스 조정 가능
- 합성 승급 확률(80/20)은 임의값 — 스테이지 난이도 곡선과 연동해 재조정 필요
- 가챠 확률(N/R/SR/SSR)은 업계 평균치를 참고한 임시값
